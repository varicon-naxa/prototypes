Scope: fix the multi-signature field we already have

Varicon already has a multi-signature field, and customers already run "supervisor fills in, crew signs" on one phone or tablet. What's broken:

  • A signature stores only a drawing and a time. Varicon doesn't know who signed, so the form is linked to the supervisor only (CS to KDW Civil, July 2026).
  • Multi-signature images render blank on the submission (VDP-1275), and a drawn signature sometimes doesn't register (VDP-1098).

This story changes three existing places, and adds no new pages:

  • Supervisor app, multi-signature field: pick the signer from the project crew, or type a visitor's name and company, then sign. Works offline (the existing offline forms).
  • Web, Forms → Form submissions → submission: the field shows a list of who signed, when, and the signature image.
  • Web, Workers → worker → Forms tab: forms this worker has signed, not just ones they submitted.

Out of this story (kept for a later one)

  • Workers signing the same submission from their own phones (RA Smith, VAR-21333).
  • External signers via a link or a QR for one submission (DMC, CQ-2796).
  • Assigning a pre-filled form to named workers, and the "who hasn't signed yet" chase.

For Tech Refinement

  • Crew list source: who appears under "On this project today"? Assumed: workers allocated to the project in the scheduler or clocked in today, then all workers via search. Needs to be available offline.
  • Existing submissions: old multi-signatures have no names. Shown as "Unnamed signature" — not backfilled.
  • Same person twice: blocked in the picker (shown greyed out).
  • Visitors: name required, company optional. Not linked to a worker record.
  • Offline: relies on the existing offline forms (PICBR-1036 open — offline forms not always available). That bug likely needs fixing first.
  • Reports/export: the submissions Excel export gets a "Signed by" column — confirm.
