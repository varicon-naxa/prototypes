What's broken today

  • Pay Items knows, Leave Types doesn't. Nine leave items arrive from Xero with a Source badge. Leave Types starts empty and has no concept of source at all.
  • Nine drawers of typing. Every type is hand-added: name, payment type, display label, description, two checkboxes. All of it re-keying data we already hold.
  • Silent drift. Add a leave item in Xero six months later and nothing tells you Varicon is now out of step.

What this does instead

  • The integration finishes the job — one review, one button, nine types created and linked to their pay item.
  • Sensible defaults, not silent guesses. Paid/unpaid read off the Xero name; sick and community service leave pre-tick attachment required. Every field stays editable.
  • Worker-facing labels get simplified. "Personal (Sick/Carer's) Leave" shows to a worker as "Sick / Carer's Leave".
  • Leave Types gains a Source column, matching Pay Items.
  • Later drift is surfaced as a banner, not left for someone to notice — see step 4.

Where this lives — two surfaces, one component

The same review table should appear in both places. It is one component, shown twice.

  • In the onboarding wizard (step 5) — a new step straight after "Connect accounting", so a brand-new customer never sees an empty Leave Types page at all. Skippable, because not every customer runs leave through Varicon.
  • After connecting Xero later (steps 1–2) — for existing customers who connect or reconnect accounting outside onboarding. Same table, reached from the integration-complete screen.

If the wizard step runs, the post-integration prompt should not fire again for the same items.

Two things to check before we write the ticket

1. What is "Payment Type" actually? The Add Leave Type drawer has a Payment Type dropdown, and the hint underneath says "if no payment type is selected, the leave type will be applied to all workers by default". I've read that as the link to the Xero leave pay item, which is what makes auto-setup possible. If it's really a paid/unpaid flag, the mapping still works but the column means something different.

2. MYOB. Same flow should hold for MYOB, but I've only modelled Xero because that's what your screenshots show. Worth confirming MYOB exposes leave categories the same way.
